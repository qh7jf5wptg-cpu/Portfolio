System Architecture

  1. Python launcher UI built with Tkinter coordinates the selected process and validates user input before execution.
  2. TwinCAT PLC project files are parsed to extract stations, variables, and device-related data types.
  3. TwinCAT HMI project files are updated with generated content and User Control assets.
  4. ADS communication is represented through generated .adsbinding files and TwinCAT HMI binding strings targeting PLC symbols.
  5. Logging, HTML help documentation, path management, validation, and exception handling are separated into common utility modules for maintainability.

Workflow Summary

From PLC Data to HMI Assets

  1. Select an automation function.
  2. The tool separates development-related and project-related workflows.
  3. The tool validates HMI project name, HMI project folder, .hmiproj file, PLC project path, and behavior-module device category when needed.
  4. PLC data is parsed and transformed into a reusable TwinCAT HMI NuGet package.
  5. Generated ADS binding strings connect components to PLC symbols for the final dynamic commissioning project.
